# Operator-first model porting

1. Inspect installed SDK, model config and framework graphs. Build feature signatures from operator + shape + dtype + strides/layout + scalar parameters + mask/alias semantics, including tensor operations outside compiled graphs. Never inspect weight binaries for operators.
2. Reuse evidence only when SDK, model revision, feature signature, kernel source hash and device/PE configuration match. States are unknown, compile_failed, runtime_failed, numerical_failed, mixed_cpu, npu_verified. Missing evidence is unknown, not unsupported.
3. Use native SDK support first. A cheap public decomposition is useful when it keeps tensors resident on NPU and does not explode dispatches. For missing or inefficient operations, prefer existing TCL, then a small new TCL kernel; use Rust/vISA only with a verified public Python bridge. Keep generic kernels separate from model adapters.
4. For each feature compare deterministic CPU references and actual NPU trace at real shapes, plus boundary shapes, padding/stride, masks, NaN/Inf and dtype cases. Predeclare tolerances. Numerical failures block integration acceptance even when images look plausible.
5. Batch independent reference/export/compile work. Bound workers times threads to available CPU cores, and memory to measured budgets. On one fusion=8 card, begin with exclusive execution. A two-process correctness probe must demonstrate resource sharing and per-process trace attribution before enabling concurrent NPU correctness jobs. Record resource contention separately from unsupported operators. Performance runs always use exclusive access.
6. Integrate only verified signatures; validate block, component, then full model. State any allowed CPU scheduler work explicitly; packing/normalization inside a model is not host control. Inspect transfer volume and dispatch count.
7. Measure cold compile, preparation/load, first forward and at least three warm forwards in the SAME process. Keep tensors/weights resident and synchronize by the installed official API. Separate profiler-enabled audit runs from throughput runs. Compare CPU only with identical model, shape, dtype, steps and prompt; a user's approximate CPU time is not a controlled baseline.
8. Low utilization: use union of NPU Task intervals (not a sum across PEs), longest host gaps, H2D/D2H bytes, kernel count and warm latency. Identify the largest measured cost before optimizing. Reuse warmed execution objects, reduce transfer/dispatch count, and fuse small ops via TCL where justified. Never declare trace coverage alone to be efficient NPU support.
9. If public paths fail, record a minimal reproduction and one precise compiler research question in REA_BACKLOG. REA is review-only in this phase; no closed binary inspection or patching.
10. Deliver an evidence table and concise HTML/Markdown status, a reproducible feature command and full model command, expected output, known limits and cache/environment fingerprint. Each failure records facts, hypothesis, attempted remedy, measured outcome and next action.

SDXL lesson: r9-r11 produced images and NPU Tasks, but spatial Conv2d routes explicitly copy activations to CPU for pad/window/cat. Thus these are mixed-device runs; prior graph-only success does not establish NPU-only inference. Convert window construction to a verified resident NPU/TCL path before accepting this model.

## Measured SDXL fixes (2026-11-02)

- The original 1048.94 s timer included audit finalization; the trace pipeline span was 269.814 s. Always measure forward and profiler/report teardown separately. A per-thread interval sweep replaced a CPU-ops × annotations scan; replaying the same trace took 15.1067 s with identical category counts. Avoid claiming an exact attribution of old teardown time without original subphase timers.
- Public TCL fetch.pad + fetch.slide + direct commit had invalid retained axes in this SDK. An explicit operation.contract against a resident unit tensor with output axes [N,Hf,Wf,Hw,Ww,C] compiled and copied windows exactly.
- Representative [1,640,32,32], [1,640,16,16], [1,1280,16,16] BF16 windows passed exact equality and 4 runtime Tasks. The 4-channel 64x64 shape failed direct DPE planning. Fixed aligned tiles plus NPU channel replication passed (92 Tasks). This is a correctness workaround with known bandwidth overhead; keep its exact signature and optimize only with fresh evidence.
- Same-card fusion=8 test overlap caused even a 655360-byte input allocation to fail. Exclusive rerun passed. Do not diagnose such errors as model OOM; record ownership and rerun exclusively.
- Set compiler Rayon budget independently from PyTorch/OMP threads; many CPU cores do not imply every small host operation benefits from 126 OMP threads. Preserve explicit user environment settings.

- Scheduler output may legitimately be CPU-resident at the model boundary. A resident-only TCL kernel should reject CPU inputs; the model adapter must explicitly transfer input to NPU before invoking it. Test adapters with CPU boundary inputs as well as already-resident NPU inputs. Do not move model arithmetic back to CPU to accommodate this boundary.
- Repeated generation measurements must run after the official profiler context closes, while keeping the same loaded pipeline and compiled objects. Use a completed CPU/PIL output as the end boundary, reset the generator for reproducibility, and retain each repeated image. Record audit finalization separately from forward latency.

Final SDXL r13: first profiled forward 282.573 s; audit finalization 58.381 s; same-process warm forwards 2.323/2.283/2.293 s. Full first-forward trace confirmed 464 graphs and 11,040 Tasks. Three warm images matched the earlier mixed-device r11 PNG exactly. Do not confuse these steady-state timings with new-process cold latency; do not mark unresolved CPU-context attribution or prior BF16 numeric gates as solved.

## CPU event and precision diagnosis

- CPU profiler events include dispatcher, tracing and fake-tensor computation. Never classify an event as concrete CPU model arithmetic from its CPU timeline category alone. Inspect actual tensor device/type and callsite during a warmed inference; keep unobserved operator families unknown. Instrumentation must have positive CPU and fake/meta negative controls.
- TorchDispatchMode and TorchFunctionMode diagnostic contexts changed RNGD eager compilation/cache behavior during SDXL warm runs (cached-output deserialization and empty output-tree errors). Preserve failed diagnostics; prefer bounded Python function-call observation when dispatch instrumentation changes the tested program. Python hooks are partial coverage and can invalidate Dynamo guards, so exclude diagnostic runs from latency measurements.
- Bisect numerical drift using each stage's actual NPU input against CPU BF16 and FP32 references. Label CPU reference work as diagnostic-only; never ship it as fallback. SDXL block2 first ResNet passed while Attention introduced violations. Manual SDPA previously rounded QK score, scale and probability intermediates to BF16. Public math SDPA parity requires FP32 intermediates for low-precision input, then cast the final result back. This change requires real-shape NPU, mask and full block validation; do not declare a precision fix complete just from this hypothesis or relax tolerances.

- Use `tools/npu_watch.py` for human-readable live SMI plus JSONL/Markdown evidence. Installed SMI JSON `pe_utilization` already uses percentage units; compare against normal CLI before conversion. A 120-second test captured 238 samples, no errors, peak 83.943%, while DRAM remained reported zero. Retain raw JSON for reprocessing and distinguish telemetry from operator Task evidence.

- Numerical reports must separate violating tensor elements, failing stage observations, implementation families, and proven root causes. Group first by operator implementation, then shape/dtype/layout; do not label thousands of output elements as thousands of bugs or sum aliased output leaves. `tests/summarize_numeric_families.py` preserves observations and reports the first failing stage per family. Current stage grouping identifies two failing Attention observations and zero failing ResNet observations; independent root-cause count remains unknown.
- FP32 manual SDPA is experimental behind `FURIOSA_SDPA_FP32=1`: it reduces observed violations but has not passed full numerical acceptance. Preserve the prior default until real-shape numerical and performance gates pass. Record this flag in reproduction commands and cache fingerprints.
